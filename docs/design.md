# 设计说明

## 目标

把一次真实操作，自动转换成"编号步骤 + 每步一张带标注的截图 + 一句说明"的图文教程。

## 非目标

- 不做录屏视频，不处理视频流
- 不做 AI 写整篇教程，文字说明由规则模板生成，人工可改
- 第一期只支持网页内操作（浏览器扩展），不做桌面任意软件录制

## 数据模型

一条事件记录：

```json
{
  "seq": 3,
  "type": "click",
  "url": "https://jw.example.edu/select",
  "title": "选课页面",
  "x": 412,
  "y": 318,
  "vw": 1440,
  "vh": 900,
  "dpr": 1.25,
  "w": 130,
  "h": 48,
  "tag": "button",
  "label": "提交",
  "shot": "auto-tutorial/003_1770000000000.png",
  "ts": 1770000000000
}
```

一条步骤记录（由事件聚合而来）：

```json
{
  "index": 1,
  "kind": "input",
  "tag": "input",
  "label": "学号",
  "text": "在【学号】输入学号",
  "value": "",
  "image": "steps/001.png",
  "box": [220, 180, 420, 230],
  "mosaics": [{"x": 10, "y": 20, "w": 80, "h": 30}],
  "suspect": false,
  "count": 1
}
```

- `box`：红框在裁剪图上的相对物理像素坐标 `[x0,y0,x1,y1]`，复核页拖动/缩放后回写；
- `mosaics`：人工框选的马赛克区域（裁剪图相对坐标）；
- `suspect`：疑似点在表单/卡片空白处的游离点击，复核页标黄提示优先检查。

输入类步骤不在教程里展示具体填写内容：密码类打码为 `••••••`，其余输入框的真实值在中间结果里清空，文案按标签写成「输入账号 / 学号…」；下拉框（`tag=select`）保留所选选项文字，文案写成「选择【选项】」。图片层面不做自动脱敏，需要隐藏的区域在复核页人工框选马赛克。

## 处理流程

1. **采集**：扩展监听 click / change / input，input 400ms 防抖后上报；事件即时登记（`seq`、`ts`、坐标、元素文字、宽高、dpr）；点击即时截图给按钮定位，输入完成 400ms 后批次截屏；点结束录制时自动导出 `events.json`
2. **抽帧**：同字段的点击与随后输入合并为一步；同一输入框的多次输入（防抖批次 + 失焦 change）合并为一步；复选框/单选的 click 与 change 跨类型合并；同一控件（矩形几乎重合）上的连续点选合并为一步（用于图形验证码）；其余每个点击独立成步。相邻同控件且画面几乎无变化的重复帧再合并一次。容器把多个字段文字拼在一起的聚合标签判无效，回退到元素类型名
3. **裁剪**：以元素外接框为中心裁出 680×400 物理像素的焦点区域（尺寸可由 `--crop-w/--crop-h` 调整），框外压暗；缺图时生成占位标注图
4. **标注**：按元素真实宽高（×dpr）画 3px 红框 + 序号圆圈；读不到尺寸时退回固定经验值；复核页人工框选的马赛克区域在裁剪图上做高斯模糊；人工调整过的红框坐标随 `box` 回写，二次成文沿用
5. **成文**：Markdown / Word(docx) / 静态 HTML 模板；步骤文字由规则模板生成（点击【X】/ 在【X】输入…/ 选择【X】），输入类具体值不进教程
6. **复核**：另出 `review.html` 复核页，直接展示成品标注图；顶部缩略导航可跳转；可删除多余步骤、修改文案，拖手柄或用 ↑/↓ 调整步骤顺序；红框可拖动、右下角手柄缩放；在图上拖框添加/撤销/清空马赛克；疑似游离点击步骤标黄；导出 `steps.json`（含文案、顺序、马赛克区域与红框）后用 `--steps` 跳过合并二次成文

## 关键算法

**关键帧判定**（最容易做砸的一步）：

- 一级规则：每个点击事件必留一帧（点击是明确意图）
- 二级规则：纯滚动、移动、hover 不留帧
- 三级规则：点进输入框后在同一框内输入，合并为一步；勾选动作的 click/change 合并；同一控件上的连续点选（验证码）合并
- 兜底：草稿生成后在复核页（`review.html`）删除多余步骤、修改文案，导出 `steps.json` 用 `--steps` 重新成文

**坐标换算**：Windows 上 125% 缩放会让 `clientX` 与截图像素错位，必须用 `devicePixelRatio` 换算：
截图像素坐标 = 事件坐标 × dpr。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 截图坐标与点击坐标错位 | 红框画歪，演示翻车 | 记录 dpr，换算后做一次可视化校验 |
| 抽帧过多 | 教程变成流水账 | 三级合并规则 + 人工删减 |
| 页面懒加载 / 弹窗晚出现导致截到空白 | 截图无内容或点选序号没进图 | 事件后延迟 400–600ms；扩展提供 `capture-now` 手动补截图；必要时重录 |
| 登录成功跳转到新页面 | 新页面操作采不到 | 一期明确范围，跳转后流程留作二期 |
| 点到表单/卡片大容器空白处 | 框偏大、标签是聚合文本 | 扩展端退回点击位置的固定小框；误判的验证码只认 img/canvas 或标签含验证码关键词；多余步骤在复核页删除 |
| 扩展只能录网页 | 范围受限 | 明确写进范围说明，桌面端留作二期 |
