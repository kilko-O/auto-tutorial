# 设计说明

## 目标

把一次真实操作，自动转换成"编号步骤 + 每步一张带标注的截图 + 一句说明"的图文教程。

## 非目标

- 不做录屏视频，不处理视频流
- 不做 AI 写整篇教程，文字说明由规则模板生成，人工可改
- 第一期只支持网页内操作（浏览器扩展），不做桌面任意软件录制

## 数据模型

一条事件记录：

```json
{
  "seq": 3,
  "type": "click",
  "url": "https://jw.example.edu/select",
  "title": "选课页面",
  "x": 412,
  "y": 318,
  "vw": 1440,
  "vh": 900,
  "dpr": 1.25,
  "tag": "button",
  "label": "提交",
  "shot": "auto-tutorial/003_1770000000000.png",
  "ts": 1770000000000
}
```

一条步骤记录（由事件聚合而来）：

```json
{
  "index": 1,
  "text": "在【学号】输入框填写学号。",
  "image": "steps/001.webp",
  "focus": [x, y, w, h]
}
```

## 处理流程

1. **采集**：扩展监听 click / change，事件即时登记（`seq`、`ts`、坐标、元素文字）；操作停止 700ms 后截一张可见区域图，这段时间内的事件共用该截图；点结束录制时自动导出 `events.json`
2. **抽帧**：同一页面上间隔小于 1.5 秒的连续事件合并；画面差异低于阈值且无文字变化的帧丢弃（当前只做时间合并，画面差异待做）
3. **裁剪**：以点击坐标为中心裁出 680×400 焦点区域（元素外接框信息尚未采集，先用固定尺寸）
4. **标注**：焦点区域画 3px 红框 + 序号圆圈，框外压暗突出焦点
5. **成文**：Markdown 模板，步骤文字生成（点击【X】/ 在【X】输入…）；docx 分支已写，未充分验证

## 关键算法

**关键帧判定**（最容易做砸的一步）：

- 一级规则：每个点击事件必留一帧（点击是明确意图）
- 二级规则：纯滚动、移动、hover 不留帧
- 三级规则：连续两次点击间隔 < 1.5 秒且在同一页面，合并为一帧，文字说明合并为"依次点击 A、B"
- 兜底：生成草稿后人工在确认页删除多余步骤

**坐标换算**：Windows 上 125% 缩放会让 `clientX` 与截图像素错位，必须用 `devicePixelRatio` 换算：
截图像素坐标 = 事件坐标 × dpr。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 截图坐标与点击坐标错位 | 红框画歪，演示翻车 | 记录 dpr，换算后做一次可视化校验 |
| 抽帧过多 | 教程变成流水账 | 三级合并规则 + 人工删减 |
| 页面懒加载导致截到空白 | 截图无内容 | 事件后延迟 400–600ms，必要时轮询等待 |
| 扩展只能录网页 | 范围受限 | 明确写进范围说明，桌面端留作二期 |
